# SWE-chat routing benchmark

Real Claude Code sessions from [SWE-chat](https://huggingface.co/datasets/SALT-NLP/SWE-chat), each replayed from its
recorded start state on a grid of 7 cells (model tier × effort) drawn from **the session's own model generation**,
and every replay judged pass or fail against acceptance criteria derived from the original session.

The question it answers: for a coding session, which (model, effort) is the cheapest that still completes the task,
and how much a router that picks it at the first user message could save against the model and effort the user
picked by hand.

**43 sessions** from 26 repositories, 301 replays, all labelled. Numbers: [`docs/results.md`](docs/results.md).

| | |
|---|---|
| Source | SWE-chat v2, revision `df393df57195593d4227aefc31f691f01d4b81a5` (ODC-BY). The original transcripts are **referenced by session id, not copied**; replay transcripts and turn scripts contain the original users' messages, because they are replayed |
| Grid | Haiku tier with no effort setting; Sonnet and Opus tiers × low / medium / high, from the original's generation (generation 5: Haiku 4.5, Sonnet 5, Opus 5; Opus 4.8 / 4.7 originals: Haiku 4.5, Sonnet 4.6, Opus 4.8 / 4.7). No model newer than the original is used, so no candidate can have seen the session or its outcome |
| Replays | One per cell: Claude Code 2.1.304 headless on Amazon Bedrock, one locked-down container per replay, package registries limited to versions published before the session, and an emulated user (the generation's Sonnet) for the later turns |
| Labels | A Fable 5.1 judge per replay and per acceptance criterion; a first verdict below confidence 0.7 gets two more and the majority decides; 3 cells carry a human override |

## Definitions

- **Cell**: `<model>__<effort>` (e.g. `claude-sonnet-5__medium`); its tier form `sonnet__medium` is comparable across generations.
- **Hand-picked**: the model and effort the user ran the original session with.
- **Baseline cell**: the hand-picked tier at the hand-picked effort within the grid (Fable → Opus; xhigh / max → high).
  `baseline_is_proxy` marks the sessions where this is not the hand-picked model and effort itself.
- **Pass**: every applicable acceptance criterion met.
- **Cheapest passing cell (oracle)**: the passing cell with the lowest replay cost. Costs are label costs: the first
  request of each model is priced with cache reads as writes, so no cell profits from another's warm cache.
- **Oracle ceiling**: 1 − Σ cheapest-passing cost / Σ baseline cost over the sessions whose baseline passed: the most
  a perfect router could save on this data without losing completion.
- **Original completed**: the task analyst's reading of the original session, `yes` or `partial`.

## Using it

```
python3 scripts/results.py            # recompute docs/results.md
```

The tables are plain CSV; per-session files are JSON, gzip-compressed where large (`docs/data-format.md`). No
train/test split is fixed; if you tune a router on this data, split by repository (`repo_id`) so that no repository
appears on both sides.

## Privacy and removal

The replays carry the original users' messages and code from public repositories (MIT, Apache-2.0, Unlicense and
AGPL-3.0 licensed). SWE-chat redacted personal information before release; this build additionally replaced
credential-shaped strings with `<redacted:kind>` (`data/redactions.json`) and masked infrastructure identifiers. If a
session is removed from SWE-chat, or you want content removed from this benchmark, open an issue naming the
`session_id`; it will be removed here too.
